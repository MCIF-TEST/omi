## STEP 1 — THE DAILY FOUNDER OPERATING CHECKLIST

One protected calendar block daily (the 6B 15-minute core; expands to ~2h on
send/call days). The day is "done" when the checklist is done — not when
you're tired. Completion is binary and logged.

**Every day, in this order (priority order if time is short):**
1. **Respond** — every prospect reply answered <24h (this outranks all else).
   Interested prospects offered two concrete call times. ☐
2. **Follow up** — T+3d nudges and T+10d closes that are due TODAY, sent.
   Terminal statuses set + bench refilled same day. ☐
3. **Outreach** — sends due per the wave plan, sent. If no sends are due,
   write "none due" — an explicit zero, not a blank. ☐
4. **Capture evidence** — any call from today: note finalized + four-box
   analysis done within 60 min; verbatims pasted; tracker statuses current. ☐
5. **Learning review** — the 3 daily numbers (opens / own-scans / new WTP),
   once, not hourly. ☐
6. **Log the line** — DAILY_LOG row: `date | sent | replies | opens |
   own_scans | calls | 1 verbatim | checklist done Y/N`. ☐

Rules: items 1–2 are never skippable; if only 15 minutes exist, do 1, 2, 6.
Sourcing new prospects is **only** permitted when no sends/replies/follow-ups
are due (sourcing is the classic avoidance task — see FM-8). Repo stays
closed (FM-2) absent an F4.

## STEP 2 — THE WEEKLY EXECUTION REVIEW

Execution quality is measured **independently of results** — by inputs, which
you control. A week of perfect inputs with zero replies is a *successful
execution week* producing negative market evidence. A week of missed inputs
with great replies is an *execution failure* that got lucky.

**Input metrics (founder-controlled — execution):** sends vs. wave plan ·
% replies answered <24h · follow-ups sent on schedule · call-booking latency
(<72h from interest) · % call notes finalized same-day · daily checklist
days (≥6/7) · repo hours (0 absent F4).

**Process-quality metrics (instrument fidelity — validation):** cold read
performed in every call · WTP + own-case close asked in every call · banned
phrases avoided · ledger updates cite N-### · balanced verbatims in Friday
review · contradiction protocol applied.

**Outcome metrics (market-controlled):** replies, opens, cases, trust quotes,
WTP — read but never graded as execution.

**The three-failure separation (diagnose in this order):**
| Failure type | Definition | Test | Verdict allowed |
|---|---|---|---|
| **Execution failure** | input metrics missed | sends late? replies slow? notes missing? | "I didn't run the test." Fix behavior; outcomes this week say nothing about the market. |
| **Validation failure** | inputs hit, instruments violated | leading questions? no cold reads? WTP skipped? cherry-picked review? | "I ran a corrupted test." Evidence quarantined; re-run with fidelity. |
| **Market failure** | inputs hit + instruments clean + outcomes negative | waves on time, personalized, iterated across ≥2 waves, and still <10% reply / no cases | the ONLY condition under which negative outcomes count as market evidence |

**License rule:** you may not attribute an outcome to the market until
execution AND process quality are demonstrated for that period. "Nobody
wants this" is a conclusion you must *earn* with clean inputs.

## STEP 3 — THE FOUNDER ACCOUNTABILITY FRAMEWORK

Objective avoidance indicators — each numeric, each checkable from the logs,
none answerable from memory:

| Avoidance pattern | Objective indicator (trigger) |
|---|---|
| **Avoiding outreach** | sends due vs. sent gap ≥2 days · wave N+1 start slipped past schedule · sourcing activity logged while sends were due |
| **Avoiding difficult conversations** | interested prospect unbooked >72h · follow-up skipped specifically for someone who pushed back · WTP asked in <80% of completed calls · own-case close asked in <100% · **zero rejections logged in 14 days** (you aren't asking real closes) |
| **Retreating into product work** | repo commits/hours >0 without an F4 · "quick fix" performed mid-window · analytics checked >1×/day |
| **Collecting without acting** | call notes exist but ledger untouched ≥3 days · probes identified in reviews but absent from next calls · same action item carried 2 consecutive weeks |
| **Overplanning** | any new framework/plan document after 6H (FM-1) · tracker schema edits after Week 0 · re-polishing the prospect list past 40 rows while sends are due · re-reading plans logged as "work" |

Weekly self-audit line (mandatory in the Friday review): *"Avoidance
indicators triggered this week: ___ (list or 'none')."* An indicator
triggered twice in two weeks escalates to its FM recovery protocol (Step 5).

## STEP 4 — THE EXECUTION SCORECARD (minimum valid week)

Nine binary behaviors. Score = count of YES.

| # | Behavior | Bar |
|---|---|---|
| 1 | Wave sends per plan (or explicit "no wave due") | 100% of due sends out |
| 2 | Replies answered <24h | 100% |
| 3 | Follow-ups (T+3 / T+10) on schedule | 100% of due |
| 4 | Interested → call offered <72h | 100% |
| 5 | Call notes + four-box analysis same-day | 100% of calls |
| 6 | Daily checklist completed | ≥6 of 7 days |
| 7 | Friday review done, all sections, balanced verbatims | yes |
| 8 | Ledger updated with cited evidence (if any calls/replies occurred) | yes |
| 9 | Repo hours = 0 (absent F4) and no new planning docs | yes |

**A valid campaign week = score ≥7 AND the hard three are YES (#1, #2, #5).**
- Invalid week → the week's outcomes are quarantined as market evidence
  (Step 2 license rule) and the missed behaviors become next week's first
  priority.
- **Two consecutive invalid weeks → execution intervention:** run the FM
  registry top-to-bottom, identify the active failure mode, apply its
  recovery protocol, and shrink the unit of work (see FM-5) until valid weeks
  resume. Track against F8 (≥15 quality conversations by week 3) — execution
  failure is the most common cause of F8, and F8 voids the whole campaign's
  conclusions.

## STEP 6 — THE MONTHLY EXECUTION AUDIT

Run **before** the 6G monthly validation review, same sitting. Answered with
numbers from the logs — never from memory. Three questions, one verdict.

**A. Did I execute the system correctly? (execution fidelity)**
- Valid weeks (Step 4): __ / 4 (pass: ≥3)
- Daily checklist days: __ / ~30 (pass: ≥24)
- Hard-three compliance across the month (sends / 24h replies / same-day
  notes): pass/fail each
- Avoidance indicators triggered + FM protocols applied: list
- Repo hours + new planning docs (must be 0 / 0 absent F4): __

**B. Did I gather enough evidence? (sufficiency)**
- Quality conversations: __ (trajectory vs. F8: ≥15 by week 3, 25 target)
- All three segments actually worked (full waves each): Y/N
- Evidence-class mix: % behavioral ≥ 50%: Y/N
- Ledger rows updated with citations: __ · balanced verbatims on file: Y/N

**C. Can the conclusions be trusted? (instrument fidelity)**
- Cold reads performed: __ / calls · WTP asked: __ / calls (≥80%) ·
  own-case close: __ / calls (100%)
- Contradiction protocol applied where contradictions existed: Y/N
- Any threshold bent without the shame line: Y/N (any Yes = taint)
- Anti-panic violations (single-event changes, recency edits): count

**Verdict (binding):**
- **TRUSTED** — A pass + B sufficient + C clean → this month's evidence may
  feed the 6G decision review at full weight.
- **PARTIAL** — name exactly which conclusions stand (e.g. "segment
  concentration is trustworthy; WTP data is not — closes were skipped") and
  which questions must re-run. The 6G review may only consume the named-
  trustworthy subset.
- **UNTRUSTED** — A or C failed broadly → the month's outcomes are
  re-labeled *pilot learnings about execution*, not market evidence. The 6G
  review's only available verdict is CONTINUE-with-corrections; the campaign
  clock extends rather than concludes. You may not stop, pivot, or declare
  victory on a month you didn't validly run.

One-page audit memo filed with the decision memo: execution grade, evidence
grade, trust verdict, the single biggest execution gap, and next month's one
corrective commitment.
